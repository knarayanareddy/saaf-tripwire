One guard · built from 50 real repos

The bad actor trips the wire before the code ships.

We attacked every SAAF agent repository, proved each weakness with a before-and-after test, and turned what kept repeating into one guard any SAAF repo can switch on in three lines.

The bad actor · Agent-Auditor (SA-07)

An auditor runs Agent-Auditor on their laptop and opens an ordinary-looking web page. That page quietly tells the tool to create a branch and commit the attacker’s text to any GitHub repo the auditor can write to, under the auditor’s name. Two lines made it possible: the server accepts calls from any website, and it asks for no login.

How it works

One engine, three faces

The engine is plain, offline Python: no AI model in the loop, same answer every run, a whole repo in seconds. Each face is a thin wrapper around the same engine.

01 · CI check

Stops it at the door

Runs on every push and pull request. Fails the build on serious findings and shows each one on the exact line in the pull request.

02 · Reusable workflow

Reads the whole past

One shared workflow for every repo. It also scans every old commit for keys, because deleting a file does not delete it from history.

03 · Claude skill

Keeps the AI honest

Wraps every auditee document so the model treats it as evidence, never as orders, and rejects any quote that is not really in the document.

Adoption

Three lines, any SAAF repo

1 · CopyAdd one file: .github/workflows/tripwire.yml
2 · PinPoint it at a fixed Tripwire release, so nobody can swap the guard
3 · PushEvery push and pull request is checked from then on
name: SAAF Tripwire
on: [push, pull_request]
permissions: { contents: read, security-events: write }
jobs:
  tripwire:
    uses: SAAF-Project/saaf-tripwire/.github/workflows/tripwire.yml@<release-sha>
    with: { tripwire-ref: "<release-sha>" }  # optional: baseline: tripwire-baseline.json

Old repo with old problems? Record today’s findings once with --write-baseline, then --baseline fails only on new ones. Clean up the backlog at your own pace.

Honest limits

What it catches, and what it does not

Catches, every time

  • Keys and tokens committed now or in the past
  • Servers open to the network or to any website
  • Untrusted text pasted into web pages unescaped
  • CI pipelines an outsider can hijack or swap out
  • Approval gates that log a failure and carry on

Leaves to people and the skill

  • Whether a business rule is the right rule (it checks that gates fail closed, not what they should decide)
  • Whether an AI agent’s verdict is right (the skill checks its quotes are real)
  • Weaknesses in a running system rather than its code
