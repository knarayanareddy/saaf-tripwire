# Findings detail

One section per record in `findings.json`; generated by `render.py`. `Before`/`after` are the observed outputs, not intentions.

## TW-A1 — A committed .gitattributes can name a textconv driver, and `git log -p` executes it while scanning history. `--no-ext-diff` does not stop textconv, so the audited repo runs code as the CI user.

- **Verdict** confirmed · **Severity** high · **Status** fixed · **Class** `web-protocol-and-auth` · **Component** rules/sec_secrets.py history scan

**Data flow**

- `tripwire/rules/sec_secrets.py:212` — git log -p --all piped to _KEY regex
- `.gitattributes:1` — *.txt diff=evil (auditee-controlled)
- `.git/config:1` — diff.evil.textconv = /tmp/hostile/evil.sh

**Probe** `python docs/self-audit/probes/probes.py A1`

Expectation: raw `git log -p` creates pwned.txt; tripwire scan does not.

**Before the patch** both plain `git log -p` and `tripwire scan` created pwned.txt; scan exited 0

**After the patch** raw git still executes the driver; `tripwire scan` creates nothing and exits 0

**Fix** tripwire/util/gitcmd.py runs every git call with -c diff.<n>.textconv= empty, --no-textconv on log, and GIT_CONFIG_NOSYSTEM/GLOBAL

## TW-A8 — PyYAML is imported by gha.py but was not a declared dependency, and the action installed with --no-deps. On a clean runner every scan died with ModuleNotFoundError, so the shipped gate could not run at all.

- **Verdict** confirmed · **Severity** high · **Status** fixed · **Class** `supply-chain-and-release` · **Component** action.yml + pyproject.toml

**Data flow**

- `tripwire/util/gha.py:11` — import yaml
- `pyproject.toml:15` — dependencies = []
- `action.yml:40` — pip install --no-deps

**Probe** `python docs/self-audit/probes/probes.py A8`

Expectation: PyYAML is declared, pinned in the action, and a clean venv with only that wheel can run a scan.

**Before the patch** fresh venv + `pip install --no-deps .` → scan exit 1: ModuleNotFoundError: No module named 'yaml'

**After the patch** fresh venv + staged tripwire + PyYAML==6.0.2 → finds the history secret, exit 1 (the finding), no import error

# Disproved candidates

## TW-R1 — Candidate: catastrophic backtracking in a rule regex on pathological auditee input.

- **Verdict** rejected · **Class** `resource-exhaustion` · **Component** regex-based rules

**Why it was raised** `tripwire/rules/check_quotes.py:1` the most backtracking-prone pattern

**Observation that killed it** 16 rules over 5 files completed in 379 ms; no single rule over 0.2 s; 4 MB neutralise 0.82 s, check_quotes 0.35 s (linear).

## TW-R2 — Candidate: an auditee document can close the fence early and escape neutralisation.

- **Verdict** rejected · **Class** `ai-and-llm` · **Component** tripwire/fence.py

**Why it was raised** `tripwire/fence.py:1` neutralise() rewrites < > and fence markers

**Observation that killed it** 30+ payloads (nested fences, uppercase, zero-width, HTML comments, markdown headings) leave no `<`, `>`, or fence marker in the neutralised body.

## TW-R3 — Candidate: a tracked symlink or parent-repo path makes the scanner read outside the scanned root.

- **Verdict** rejected · **Class** `data-isolation` · **Component** safeio + engine

**Why it was raised** `tripwire/util/safeio.py:1` is_safe_file / check_bytes reject escapes

**Observation that killed it** tests/test_symlink_safety.py: /etc/passwd target and /dev/zero are refused by realpath containment and S_ISREG; no bytes cross the boundary.

## TW-R4 — Candidate: an auditee filename injects a second SARIF result or breaks the JSON document.

- **Verdict** rejected · **Class** `client-side` · **Component** report SARIF

**Why it was raised** `tripwire/report.py:118` json.dumps handles escaping

**Observation that killed it** newline/quote/C1 filename: output parses as JSON, one result, uri is a single escaped string (control chars removed by _safe).

## TW-R5 — Candidate: an auditee file crashes one rule and hides the rest of the findings.

- **Verdict** rejected · **Class** `business-logic` · **Component** engine rule isolation

**Why it was raised** `tripwire/engine.py:44` per-rule try/except

**Observation that killed it** rule errors are recorded and force exit 2 (fail closed); findings from the other 15 rules are still emitted, so a crash cannot be used to pass the gate.
